# Host isolation: do not use the Sense client page

A migrated extension must run only on what it ships plus the stardust API. It must not use APIs, frameworks, DOM, or CSS that belong to the page hosting it (the Qlik Sense client). The same extension then keeps working when the host page changes, and it can be embedded outside Sense.

This is a hard rule of the skill, enforced twice:

- `scripts/check-no-host-apis.mjs <project>` scans the source.
- `scripts/check-no-host-apis.mjs <project> --bundle <ext-folder>` also scans the built output. The generated AMD wrapper may depend only on `./...` and `@nebula.js/stardust`.

Run it without `--allow-shim` before you hand the result over.

## What is forbidden, and what to use instead

| Forbidden (host page) | Use instead |
|---|---|
| `window.qlik`, `define(['qlik'], ...)`, `require('qlik')` | `useApp()`, `useModel()`, `useGlobal()`; see `app-and-navigation.md` |
| AngularJS: `template`, `controller`, `$scope`, `$timeout`, `ng-*`, `angular.*` | Plain DOM or a bundled UI library; see `angularjs-rewrite.md` |
| `qvangular`, `autogenerated/*`, `util`, `general.utils`, `client.utils/*`, `core.utils/*`, `objects.*` | Remove; there is no public equivalent |
| Host jQuery / underscore through `define`/`require` | Native DOM and array methods, or add the library to `dependencies` so it is bundled |
| Host DOM: `document.querySelector('.qv-...')`, `$('.qv-panel-sheet')`, any element outside `useElement()` | Operate only inside the element you were given |
| Host CSS classes: `.qv-*`, `lui-*` (Leonardo UI classes are provided by the Sense page), `!important` overrides | Ship your own namespaced CSS; read colors and fonts with `useTheme()` |
| Global CSS: `<style>` in `document.head`, Bootstrap loaded globally | Scope styles to your element; see `styling-and-assets.md` |
| A second engine connection (`enigma.create`, `new WebSocket`) | `useModel()` / `useApp()` |
| Loading scripts, styles or fonts from a CDN at run time | Install from npm and bundle; otherwise the tenant needs a CSP entry (`external-resources.md`) |
| `useConstraints()` | `useInteractionState()` |

qlik.dev lists the same five anti-patterns (host DOM, global CSS, internal modules, oversized fetches, extra sessions) in its extension guidelines. See `sources.md`.

## What is allowed

- `@nebula.js/stardust` hooks and the `galaxy` argument.
- Any npm package listed in `package.json` `dependencies`, which `nebula build` bundles. `@nebula.js/stardust` is a `peerDependency` and is the only external.
- A bundled copy of jQuery, underscore or a UI framework. jQuery is allowed only as a declared dependency, never from the host, and it is discouraged: prefer native DOM.
- **Guarded** use of `galaxy.anything.sense` (`theme`, `navigation`), which exists only inside Sense:

  ```js
  const sense = galaxy.anything?.sense;       // undefined outside Sense
  const theme = sense?.theme;
  ```

  The extension must still render without it. The checker warns about unguarded access.

## The `jquery` warning in the console

Qlik Cloud logs `Detected extension usage of unsupported APIs "jquery"` on every page load (observed October 2026). **It is not evidence about your extension:** it appeared on pages that load no extension script at all, and in every run exactly once.

- Requesting another wrapped module does warn: running `requirejs(['underscore'])` from the console logged one, so an `underscore` warning is a real signal.
- Reading or calling `window.$` / `window.jQuery` is silent.

Do not use the `jquery` warning to decide whether an extension depends on jQuery. Check the extension:

1. AMD dependencies: `check-no-host-apis.mjs --bundle <folder>` fails any `define([...])` dependency other than `./...` and `@nebula.js/stardust`.
2. Free globals in the built bundle: the ESLint check below.
3. For modules not requested on every page, wrap `console.warn` to record `unsupported APIs` messages with a stack, then load the extension for the first time in that page session.

## Checking for assumed globals (deeper than `check-no-host-apis`)

The scanner looks for named host APIs. To list *every* free global a built bundle uses, which is what "assuming something is on the page" means, run ESLint's undefined-identifier rule over the built file (needs `eslint`, so it is not part of the bundled scripts). Use ESLint 8: version 9 removed `--no-eslintrc` and `--env`, and the scaffold's `.eslintignore` lists `dist`, so without `--no-ignore` ESLint skips the file and exits 0 (a false pass):

```bash
npx eslint@8 --no-eslintrc --no-ignore --env browser,es2022 --rule 'no-undef: error' --global stardust,define,exports,module,require <nebula-id>/dist/<nebula-id>.js
```

Expect no output beyond the UMD wrapper and `stardust`. Anything else is either a feature-detect in a bundled library (read the context: `typeof x`, `try/catch`) or a real host dependency. In bundles built from real extensions only one bundled library, a spreadsheet library (ExcelJS), reported names: five library-internal ones (`ActiveXObject`, `Deno`, `msCrypto`, `regeneratorRuntime`, `global`), all feature detection. One of them, a Babel runtime, can *assign* a `regeneratorRuntime` global onto the host page: harmless, but bundled libraries can leak globals, so check for it.

## Guarded fallbacks to host-supplied objects

Property-panel callbacks receive objects from the Sense client (for example `handler.app`). Duck-typing one defensively is tolerated as a **fallback only**: check `typeof x.createSessionObject === 'function'`, never assume a wrapper shape such as `app.model.enigmaModel`, make the feature degrade (an empty list plus a typed value still works), and record it in MIGRATION.md. `check-no-host-apis` reports these as warnings (`host.app-model`, `app.sheetlist`). Anything that works only because of such an object is not allowed in `component()`.

## Property panel

`ext.definition` is evaluated by the Sense client, and it can technically host an AngularJS custom component (`component: { template, controller }`). This skill does not use that. Replace a custom component with built-in ones (`buttongroup`, `dropdown`, `switch`, `slider`, `color-picker`, `button` with an `action`, `link`, `text`), or move the feature into the chart itself.

## Quick triage of an inventory

`scripts/inventory.mjs` puts hits in four buckets. `host` hits must all be gone at the end. `rewrite` hits are redesign work. `direct` hits have a mapping row. `review` hits need a look at the context (for example `document.querySelector` scoped to your own element is fine).
