# Scaffold, build, package, upload

Last tested with `@nebula.js/cli` 7.6.0 and Node.js 24 (October 2026). Check the current version and its Node requirement before relying on the commands below (`npx @nebula.js/cli --version`, `--help`). Ask before running `npx` or `npm install`.

## 1. Scaffold (in a new folder next to the legacy extension)

```bash
npx @nebula.js/cli create <nebula-id> --picasso none --pkgm npm
```

- There is no `--type extension` flag. A visualization is the default. Other options: `--typescript`, `--install false`, `--author`, `--pkgm npm|yarn|pnpm`. Without `--picasso` it prompts.
- Name the project with the side-by-side id from `node <skill>/scripts/nebula-id.mjs "<original id>"` (`<original-id>-nebula`, see `compatibility-and-rename.md`).
- Generated by that version (re-check with `npx @nebula.js/cli create --help`): `package.json` (scripts `build`, `start`, `sense`, `test:e2e`), `src/index.js`, `src/object-properties.js`, `src/data.js`, `src/ext.js`, `src/meta.json`, `test/component/hello.fix.js`, `test/integration/hello.e2e.js`, lint and Playwright config. `peerDependencies` has `@nebula.js/stardust >=7.0.0`.
- Review `author` (git name and email, copied into the `.qext`), replace the Hello tests, and add the original licence (`testing-without-sense.md`).

Then in `package.json` set the `sense` script to write a folder that matches the id:

```json
"sense": "nebula sense --meta src/meta.json --output <nebula-id>"
```

and in `src/meta.json` set `name` (display name, `Nebula <Original name>`) and `icon` (one of the documented values below), plus `preview` if you ship one. **The `.qext` `description` is taken from `package.json` `description`, not from `meta.json`** (`nebula sense` reads `supernovaPkg.description`), so set it there.

### Licence, preview, author

- **Licence.** Keep the original licence as `LICENSE.txt` in the project. If the legacy folder has none, write one from the licence header or the `.qext`, say it needs the upstream text, and add the licence texts of the libraries you bundle (the minified bundle does not carry them). `nebula sense` does not copy it: copy it into the output folder after every `npm run sense` and again after the rename, and into the zip. A file named `LICENSE` is ignored by Qlik Cloud and `check-package` warns.
- **Preview.** `"preview"` in `src/meta.json` is resolved from the project root and copied to the same relative path. Put the image in the project root and use `"preview": "preview.png"`; in `src/` it is not found.
- **Author.** The generated banner and `.qext` use `package.json` `author`. A name without an email prints `<undefined>` in the banner. Keep the original author name; add the email only if the legacy `.qext` has one, and tell the user what you set.

Valid `icon` values are listed on the QEXT file page (https://qlik.dev/extend/extensions/qext-file-overview/); `check-package.mjs` warns on a value outside the list it knows, which can lag behind that page.

## 2. Build and package

```bash
npm run build      # nebula build  -> dist/<name>.js (UMD), dist/<name>.esm.js
npm run sense      # nebula sense  -> <output>/<name>.qext, <output>/<name>.js, <output>/dist/<name>.js
node <skill>/scripts/check-package.mjs <nebula-id> --expect-name <nebula-id>
node <skill>/scripts/check-no-host-apis.mjs . --bundle <nebula-id>
```

What `nebula sense` produces (observed): the `.qext` with `"type": "visualization"` and `"supernova": true`, plus a one-line AMD wrapper `define(['./dist/<name>'], (supernova) => supernova);`, plus the UMD bundle whose only AMD dependency is `@nebula.js/stardust`. With `--ext def.js` it also bundles an ext file and the wrapper merges it, overwriting any `ext` already on the chart. The "should be included in package.json 'files'" warnings are about npm publishing and can be ignored here.

`nebula build` facts: rollup; UMD (used by `nebula sense`), ESM, SystemJS; `package.json` `main` sets the UMD path; **every `peerDependency` is treated as external and not bundled**, so libraries you want bundled (React, d3, jQuery) must be in `dependencies`. `--typescript`, `--sourcemap`, `--mode`, `--watch`, `build.replacementStrings` in `nebula.config.js`. `--legacy` was removed from `nebula sense` in 4.0.

Zip the **folder** so the folder name is inside the zip:

```bash
zip -r <nebula-id>.zip <nebula-id>
```

## 3. Local checks that need no tenant

- `nebula serve` (dev server on http://localhost:8000) renders the visualization against a tenant or engine. It does not render `ext.definition`; it builds its panel from the data targets. Connect with a web integration ID (WebSocket URL `wss://<TENANT>.<REGION>.qlikcloud.com`, and allow `http://localhost:8000` on the integration) or an OAuth client (`--clientId`; redirect `http://localhost:8000/auth/login/callback` for nebula 5 and later).
- `nebula serve --fixturePath` / fixtures (`*.fix.js`) render a recorded layout without an engine; `EnigmaMocker.fromGenericObjects([...])` from stardust does the same in code. The scaffold uses Playwright against fixtures (`npm run test:e2e`). `@nebula.js/test-utils` is no longer published in a current version; do not depend on it.
- Capture a real `layout` from the legacy chart (browser dev tools or a Qlik engine call) and render the new code against it as a fixture.

## 4. Upload (host-specific; the user's tenant and rights)

**Qlik Cloud**: Management console > Extensions > upload the zip. Uploading needs an admin role that can manage extensions. Qlik documents limits on zip size, file size, file count and uncompressed size, and blocks some file types (the help page below has the current values; `check-package.mjs` warns against the values documented in October 2026). Files without an extension are ignored. External origins used by the extension must be in the tenant's content security policy (CSP) or requests fail with no error in the UI. Downloading an extension archive is restricted to admin roles (see the help page).

Scripted: `POST /api/v1/extensions` (multipart `file=@<zip>`; the response includes `supernova: true` for nebula extensions) or `qlik extension create --file <zip> --supernova`. CSP entries: `/api/v1/csp-origins`. Do not run these for the user without explicit approval: they change the tenant.

**Qlik Sense client-managed**: copy the folder to the Extensions directory (Desktop: `Documents\Qlik\Sense\Extensions`) or import the zip in the QMC.

Then, in the app: edit a sheet > Assets > Custom objects (for visualization extensions) and add the new chart.
